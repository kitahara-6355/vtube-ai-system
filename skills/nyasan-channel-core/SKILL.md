# にゃーさんチャンネルの芯

チャンネルの肝。ストーリー、台本、画、動画はすべてここに照らして作り、確かめる。
言葉の一覧の正本は `characters/characters.json`（GWS に取り込んだ zip では `references/characters.json`）。
ここに書いたことを変える時は北原さんの承認を取り、`characters.json` と一緒に直す。

確定: 2026-10-31（北原さん承認）

## 0. チャンネルの役割

よちよち社長の動画は、ゆくゆくは**法人顧客を獲得するための広報動画**（北原さん 2026-10-31。可能な限りこの判断を維持する）。`channel.purpose` が正本。

- 流れは 認知（ショート）→ 共感（中尺）→ 信頼（長尺）。ショートは認知の役割。
- キャラから入るのは、この広報の入口を広くするため。売り込みは前に出さない。
- 法人の担当者が見ても安心して紹介できる品位を保つ。PC操作の「教え」は正確に。中小企業と社長を笑いものにしない。

## 1. 芯（4つ）

1. **応援したくなる関係性**: にゃーさんは社長より「少しだけ先」で支える。専門家として教えない。
2. **現状への尊重**: 紙・ハンコ・LINE など中小企業の習慣を否定しない。その上に新しい選択肢を一つ足す。
3. **モノローグが最重要**: 行動と心の声のギャップで共感と笑いを生む。
4. **キャラクターから入る**: 入口はキャラの魅力。ストーリーは最初からしっかり仕込むが、その魅力に気づいてもらうのは後から。

他チャンネル（テイコウペンギンの理不尽、おぱんちゅうさぎの報われなさ）との差は「あたたかい職場」。見た人が「この会社で働きたい」と思う側に立つ。

## 2. キャラの魅力

`characters.*.appeal` に入口（entry: 一目で伝わる）と奥（deep: 見続けた人が気づく）が5つずつある。毎話、社長とにゃーさんから1つずつ選び、台本の `appeal` に書く。

- 一番の武器は二つのギャップ。社長「現場ではプロなのに、PCの前だと赤ちゃん」、にゃーさん「表はやさしいのに、心の声は辛口」。
- 2人の関係の魅力は `channel.relationshipAppeal`。締めで少しだけ前に進める。

## 3. 仕込み（ストーリー）

`channel.storyThreads` から毎話1つ選び、台本の `setup` に書く。説明せず、画と一言だけで置く。

- estimate-past: 社長が見積もりを上書きで消した過去（手書きにこだわる理由）
- dekita-memo: にゃーさんの「社長できたことメモ」
- genba: 現場での社長の顔（立場が入れ替わる回の準備）
- kimi-ga-ite: にゃーさんが言われたい「君がいてくれて本当に良かった」

## 4. 出す順番

`channel.releasePhases`。段階1「キャラを知ってもらう」（最初の10本ほど、入口の魅力中心、EP001 → EP003 → EP002）→ 段階2「2人を好きになってもらう」（関係の魅力、逆転回）→ 段階3「ストーリーに気づいてもらう」（仕込みを表に出す）。

## 5. 語り方の型

| 層 | 中身 | 置き場所と量 |
|---|---|---|
| 画 | 場面で起きていることはすべて画で見せる。冒頭2〜3秒は入口の魅力が一目で分かる画 | 全面 |
| 状況キャプション | 「月曜、9時。」のような短い一言。場面が変わる時だけ | 上の安全域のすぐ下（y=300〜420）。1行12字以内、1.5秒ほど |
| 心の声（ ） | キャラごとの独白。後から声を入れる（社長＝克洋さん、にゃーさん＝知人の女性） | 絵のコマの最下（y=1150〜1250）、左右は108〜900px。声を入れた後も文字は残す |
| 一言セリフ | 「あ」「ふむ」程度 | 小さな吹き出し。1話に2回まで |

- 動画は無音で作る（声は後からアテレコ）。
- ショートの下のUI（下から480〜672px）と右のボタン列には文字を置かない。

## 6. 方針ずれチェック（成果物で確かめる）

完成投稿動画が10本（段階1）になるまでは、成果物ができるたびに毎回確かめる。それ以降は機械のチェックを毎回、目で見る確認は投稿前に行う。

| いつ | 成果物 | 見るもの |
|---|---|---|
| ストーリーを増やす時 | ネタ・台本の案 | 芯1〜4、選んだ魅力と仕込み、出す順番のどこに入るか |
| 台本を書いた時 | `episodes/*.json` | 機械のチェック（下）＋一言セリフ以外が心の声か画にできないか |
| 画像が届いた時 | 生成画像・コマ一覧 | 目で見る項目、キャラの見た目が設定どおりか |
| Flow の動画が届いた時 | クリップ | 途中ズーム・表情の変化・最初の絵に戻る動きがないか |
| 投稿前 | 完成動画・投稿文 | すべての項目。法人の担当者に見せても困らないか |

### 手順（Claude Code）

1. `python tools/policy.py episodes/<回>.json` を実行する（`nyasan.py` と `manga.py` の各コマンドの後にも自動で走る）。台本の文字から NG／注意 を出し、`out/<回>/方針チェック.md` を書く。NG があれば終了コード1。
2. `out/<回>/manga/コマ一覧.jpg`（動画なら書き出したフレーム）を開いて見る。報告書の「目で見て確かめること」を一つずつ ✓／✗ で埋める。✗ には直し方を一行で添える。
3. 北原さんへは「ずれ」と「判断がいるもの」だけを短く伝える。採否を決めるのは北原さん。Claude が勝手に作り直したり、クリップを採用・削除したりしない。

### 手順（GWS の Gemini で使う時）

台本の JSON か画像を渡し、この SKILL.md の 1〜5 と `references/characters.json` に照らして、下の表で答える。生成ボタンは人が押す。

| 項目 | 結果（OK／ずれ／要判断） | 理由と直し方 |
|---|---|---|

### 機械のチェックが見ていること

- 魅力（appeal）が両キャラ分あり、設定の言葉から選ばれているか。仕込み（setup）があるか
- 冒頭のコマの文字が12字以内か
- セリフが一言（10字以内）か、1話2個までか。心の声がセリフより多いか
- 最後がにゃーさんの心の声か。尺が25〜35秒か
- 紙・ハンコ・LINE を否定する言い回し、にゃーさんの専門家口調、社長を見下す言葉がないか

## 7. 運用の約束

- Google は定額プランの範囲で使う（従量課金の API は使わない）。画像・動画の生成ボタンは人が押す。
- 品質の判断と次の生成に進むかは北原さんが決める。Flow の「常に承認」は使わない。
- キャラ画像・生成物・鍵は公開リポジトリに入れない。正本は共有ドライブ。
